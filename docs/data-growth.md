# ประวัติ git โตแค่ไหน และจะทำอะไรเมื่อไร

วัดเมื่อ 15 ต.ค. 2026 (หลังหุ่นยนต์อ่าน YouTube บน GitHub ครั้งแรก)

| ไฟล์ | ขนาดดิบ | บีบอัดแล้ว | เขียนใหม่บ่อยแค่ไหน |
|---|---|---|---|
| `data/state/videos.json` | ~805 KB | ~220 KB | วันละครั้ง (ตอนอ่าน YouTube) |
| `data/state/channels.json` | ~378 KB | ~100 KB | วันละครั้ง |
| `data/days/<วัน>.json` | ~56 KB | ~15 KB | วันละไฟล์ (เก็บถาวร = ประวัติที่ต้องการ) |
| `data/latest.json`, `ideas.json`, `history.json` | เล็กกว่า | — | ทุก 6 ชั่วโมง |

**ประมาณการ:** ประวัติ git โตราว **0.4–0.7 MB ต่อวัน ≈ 150–250 MB ต่อปี** (git บีบอัดซ้ำได้อีกบ้าง แต่ JSON ที่เปลี่ยนทั้งไฟล์บีบได้ไม่มาก)
วันนี้ทั้ง repo มีขนาด **2.7 MB** — ยังไม่ต้องทำอะไร

## เมื่อไรต้องลงมือ
เมื่อ **ขนาด repo เกิน 500 MB** (ดูได้จาก `https://api.github.com/repos/vivo0982136455-dev/mr-news` ช่อง `size` หน่วย KB) หรือครบ 1 ปี แล้วแต่อะไรถึงก่อน
GitHub แนะนำให้ repo เล็กกว่า 1 GB และ clone ช้าลงเมื่อประวัติใหญ่

## ทางแก้ที่เลือกไว้ (ทำตามลำดับ)
1. **ย้ายไฟล์สถานะ (`data/state/`) ไป branch แยกชื่อ `state`** ที่ commit แบบ "แทนที่" ทุกครั้ง (`git commit --amend` + `git push --force` เฉพาะ branch นั้น) — branch นี้จึงไม่มีประวัติสะสม หุ่นยนต์ checkout `state` มาไว้ใน `data/state/` ก่อนอ่าน แล้วส่งกลับหลังอ่าน
   ส่วน `main` เก็บแค่ไฟล์ที่หน้าเว็บอ่าน (`latest.json`, `days/`, `months/` …) ซึ่งเล็กและเป็นประวัติที่อยากเก็บ
2. ถ้าต้องการลดขนาดย้อนหลัง: สร้าง repo ใหม่จากสถานะล่าสุด (ไม่ต้องเขียนประวัติเก่าใหม่) แล้วย้าย GitHub Pages ไป — **Win ต้องตัดสินใจเอง** เพราะลิงก์และติดตั้งแอปบนมือถือผูกกับชื่อ repo
3. ไม่ใช้ Actions cache เก็บไฟล์สถานะ: cache หายได้ถ้าไม่ได้ใช้ 7 วัน ทำให้การวัด "วิวที่เพิ่มใน 24 ชม." เริ่มใหม่หมด

## อีกเรื่องที่ต้องรู้
GitHub ปิดการรันตามเวลา (schedule) ของ repo สาธารณะที่ไม่มีความเคลื่อนไหว 60 วัน — commit ของหุ่นยนต์ทุกวันนับเป็นความเคลื่อนไหว ถ้า workflow ถูกปิด หุ่นยนต์และ `check-data.mjs` จะไม่รันเลย จึง **ไม่มีอีเมลเตือน** — สิ่งที่ Win จะเห็นคือ **แถบแดง "ข้อมูล YouTube ค้างตั้งแต่…"** บนหน้าเว็บหลังผ่านไป 36 ชม. (หน้าเว็บคำนวณเองจากเวลาที่อ่าน) เมื่อเห็นแถบนี้ ให้เปิดหน้า Actions ของ repo แล้วกด **Enable workflow**
